# Implementation

## Coverage

- Shared proposal and inventory datasheet schemas define `tuckmark.agent-import.v1`, scope-only template applicability metadata, independently editable label print quantities, non-blocking attention, and link-only datasheets.
- DEVD owns shared template and inventory data, 30-minute authenticated sessions, template-input events, stale-response rejection, expiry cleanup, serial inventory commits, and recoverable all-or-nothing writes. Agent Import accepts template choices from the DEVD catalog only; browser-local templates can enter the shared directory solely through an explicit archive import.
- `DevdDataService` is the shared deep module for RuntimeStore, inventory, Agent Import, archive, revision persistence, transaction recovery, atomic JSON replacement, and SSE invalidation. It records durable directory ownership and holds a PID-scoped live lock before serving mutations, recovering only locks left by dead processes. Web `server-http` adapters for DEVD-owned records never fall back to browser storage; their resource commands are serialized locally so a completed revision always becomes the next expected revision.
- The data HTTP contract exposes status, runtime snapshots and commands, inventory queries and commands, archive inspection/import/export, backup creation, and revision SSE. Only loopback transport peers may use DEVD routes. Archive merge is pure-new and conflict-atomic; replace writes a protection snapshot in the same transaction after duplicate and cross-record reference validation. Browser-static and server-http write the same `tuckmark.runtime-export-archive.v1` directory-tree ZIP and verify its required settings entry and manifest counts before import; `tuckmark.data-archive.v1` single-snapshot ZIP files remain readable. DEVD manual and protection snapshots retain every durable runtime and inventory record, while locks, transaction journals, and session credentials stay outside backups. Server-owned template history preserves the existing 20 saved-version, 10 autosave, five-minute autosave, and 20 protection-snapshot retention contracts.
- `tuckmark agent-import` provides catalog, inventory, create, open, wait, and fulfill commands with an explicit `--devd-url` / `TUCKMARK_DEVD_URL` boundary. Confirmation links use an independently configurable `--web-url` / `TUCKMARK_WEB_URL` and persist that origin with the credential; the standard local server/Web port pairing is derived when omitted. Released and source-tree Skills guide Agents through the same contract. The Canvas workspace edits one literal suggested-use string as template metadata in a compact multiline field, while the Templates workspace batch-entry table remains dedicated to variable data. Old persisted suggestion arrays are normalized while reading and all new writes use the singular field. No score, badge taxonomy, or recommendation weight is introduced.
- The `/agent-import/:sessionId` confirmation route presents two row-oriented editable tables: primary new-material and restock intake cells display plain values until clicked, then edit that single cell. `Enter` and blur return to display mode; `Escape` restores the value held when editing began. Supplementary fields, the label preview, and template fields expand in a detail row. The import-selection column uses a compact checkbox without redundant state text, and the compact action column keeps its controls within the desktop table width. It supports DEVD catalog template choices, template wait states, stale-poll rejection, and a Storybook state gallery. Existing-material fields are displayed read-only because a restock persists only an inbound adjustment; service updates likewise retain their original target, timestamp, and material identity. The mock-only desktop result is recorded in `SPEC.md`.
- Recent-template and recent-print panels retain their browser-local presentation registry on `server-http` startup and after an interaction. That registry does not read legacy sync state, call `/api/sync`, or participate in DEVD data, archive, or backup ownership.

## Operational Boundary

DEVD must be started in `server-http` mode with `TUCKMARK_DATA_DIR` pointing at the local shared directory. `browser-static` intentionally has no compatible API implementation.

Tests and previews must use a newly created temporary `TUCKMARK_DATA_DIR` populated only with mock fixtures.
